# Laptop review studio

Start `syncloom-server` as described in the [README](../README.md), then open `http://127.0.0.1:8790/`. If using `SYNCLOOM_ADDR=127.0.0.1:0`, use the port in the listening log. Do not substitute `localhost`: exact Host matching is intentional. The page is laptop-only, not a phone access path.

## Review loop

1. Enter a thought, choose channels and select **Draft a piece**. Only LinkedIn is selected by default; zero, repeated or unknown submitted channels are refused by core. Claude drafting may take up to a minute. Saved pieces made by the CLI also appear in **Saved pieces**; this is the same store and core, not a browser-only queue.
2. Open a piece. Read the full saved text and whitespace in the approximate local preview and source thought. Natural character counts keep the core's channel-specific conservative units; closed **Details** explain the exact counting rules, bounds and full saved revision. Source-language handles are suggested review targets, never connected-account identity; existing @ prefixes are shown once. Remote fonts, folds and layouts may differ. **Edit draft** opens a separate editor without approve/publish controls. Saving a changed draft invalidates approval and previous rendered assets; canceling leaves the saved version unchanged.
3. Open **Render previews**, choose a template and enter one slide per line. This editor has no approve/publish controls, so unsaved slide changes cannot be mistaken for saved assets. Submitting **Render previews** calls the existing renderer, which may take 30 seconds. Read the PNG and scroll through the actual PDF at phone widths, or open their verified-byte links. The PDF's page count appears beside the preview; complete SHA-256 hashes are available in closed **Details**. **Local technical checks** inspect actual PNG/PDF bytes and report their decoding/geometry separately from **Visual quality: not assessed**. Open **Checks and limitations** for named observations, assessor and revision. No vision model ran and there is no overall quality score. Hash-bound preview links refuse replacement bytes; reload or render new previews if inspection fails. Meta pieces also show every JPEG slide with its exact hash; approval submits their ordered hash list. This previews a small screen on the laptop; it does not expose the server to a phone.
4. **Approve this version** submits the displayed saved revision, hashes and connected account fingerprint. A changed account or unbound historical approval shows a warning, disables Publish and enables fresh approval without editing content. A stale review form cannot approve an account different from the one displayed. A version already approved for the current account shows its actual recorded approval date without a second approve action. History-less older records say the date is not recorded. Later publishing/export times never replace approval time. Stale revisions, missing or mismatched assets, or damaged bytes fail with the same core codes as the API and CLI. No approval is silently refreshed.
5. **Publish** is separate. With no delivery grant, the result says **Not sent - saved on this laptop**; closed **Details** retain status `contained` and zero attempts, and this publish intent sent no platform post. Containment can also apply for other supported local-only cases; it is not a claim that all networking is absent. A repeated contained publish returns the same intent. LinkedIn visual uploads remain contained. Granted Mastodon, Bluesky and X delivery can upload the approved PNG; Threads supports text only and PDF carousels stay local. X displays its dated cost estimate with a separate **Accept estimated cost** form. Publish is disabled until that exact revision and estimate are accepted, then publishing remains a separate action. Consent is server-session state: changed revisions or estimates and server restart require fresh acceptance. Browser Publish refuses missing consent even without a delivery grant; JSON/CLI confirmation and core delivery refusal stay unchanged. The receipt retains the estimate, not an invented actual charge. [Connection and cost guide](social-platforms.md). Meta media delivery needs an explicitly approved public host, which is unconfigured; see [Meta integration](meta.md). Other configured outcomes, including `unknown`, are displayed as returned by the core, never renamed to posted. Review approval is not account readiness. A saved `posting` marker is an unconfirmed attempt, not proof of active progress. `posting`, `unknown` and `posted` suppress a new send. The current-revision publish receipt is read separately from the piece's last-operation summary: exporting local files cannot hide a prior unknown/posted publish, and an export does not globally prohibit a separate supported publish intent. Browser publish redirects to this saved snapshot, preserving recorded request id, attempts, remote id/URL and dated estimate when present, without inventing an actual charge.

A saved account with missing posting permission says your named platform account is connected, but Syncloom isn't allowed to post to it, and asks you to reconnect and allow posting. Permission that could not be verified says Syncloom couldn't confirm it's allowed to post to that named account, and asks you to reconnect to check again. An unconfirmed identity says Syncloom couldn't confirm this is your named account, and asks you to reconnect to check again. These sentences do not repeat raw connection status text. **Publish** is disabled and visually inactive, and **Reconnect account** stays beside the sentence. This protected native action starts the existing provider sign-in in a new tab. Return to finish reconnecting; Threads asks for the full returned callback URL through its existing flow. Completing returns to the piece and never approves or publishes it. A different connected account still requires fresh approval.

The browser's native navigation/loading indicator covers form submissions. Empty views explain where to start; errors show the fixed core/transport code and request id with a recovery link. There is no client-side script runtime. Every action is keyboard accessible and the layout works at narrow widths. The mineral-botanical palette follows the browser's light/dark preference. Prose stays 16px with slightly increased dark leading. No theme cookie or script is required. The same screens stack at narrow widths with visible keyboard focus. Disabled actions keep a readable label and do not use the accent or subtle fill, so they do not look like the enabled Publish action. [Design, tokens and source provenance](design/text-studio.md).

## Local text-file sources

Open **Start from a text file** in Workspace. Choose one local UTF-8 `.txt` or `.md` file and **Extract file only**. The native picker selects bytes, not a server path. Chrome's native picker may elide a long selected name visually, while retaining its complete accessible value. After local extraction the next page shows the complete wrapped filename, all extracted text and source provenance. Choose destinations, preview the normalized text actually sent to the drafting provider, then explicitly **Confirm and draft**. Selection, extraction, suggestions and preview make no provider call. Confirmation creates pending-review drafts only; approval and publication remain separate.

The structural contract is strict UTF-8, an optional first BOM removed, CRLF/CR normalized to LF, and all remaining text preserved. Markdown and HTML are displayed literally, never rendered or executed; links and subresources are never fetched. There is no loss replacement, truncation, OCR or semantic/model verdict. PDF, images, Office, archives and other binary formats are unsupported, including a PDF header disguised as `.txt`. Printable UTF-8 alone cannot establish authorship, meaningfulness or prompt-injection safety.

Bounds: at most 262144 original bytes, 8000 extracted Unicode scalar values, at least eight non-space characters, and a basename of 1-128 UTF-8 bytes with no path separator, control or directional-format characters. Text rejects controls except tab/newline and rejects directional-format characters. Extensions are case-insensitive `.txt`/`.md`. Claimed MIME may be absent, `application/octet-stream` or `text/plain`; `.md` additionally accepts `text/markdown`. MIME is only a hint, never proof. Two upload readers are allowed, with immediate refusal for a third; reading/parsing has a ten-second total deadline and the existing 1 MiB whole-request cap. Refusal creates no snapshot, piece or provider call.

`POST /v1/capture/attachment` accepts `multipart/form-data` with exactly one `file` part and the existing session header. Browser `POST /capture/attachment` additionally requires exactly one `csrf` form field. No supplied path, extra field, repeated/missing file or malformed multipart is accepted. Host/Origin/Fetch-Site protections remain unchanged. Success is 200 with `source_revision`, `source` and `suggestions`. Source type `attachment` uses filename as `raw_input`, plus `attachment` metadata: `filename`, validated `format` (`plain_text`/`markdown`), `byte_count`, original-byte `content_sha256`, UTC `captured_at` and full `extracted_text`. Raw upload bytes are discarded, never served or persisted. Metadata/extracted text use existing private capture/piece stores and content-free events; there is no parallel upload registry or retention policy.

Use that exact extracted `text` and `source_revision` in existing preview/confirm. Receipt, selected channels and preview revision remain bound. Native browser CRLF form serialization is canonicalized for attachment receipts only; JSON text stays exact. A restart changes the session token, not the durable receipt. A duplicate completed confirmation returns original drafts; an interrupted claim conflicts rather than retrying a provider blindly. Inspect Saved pieces before starting again. The preview shows both complete extraction and whitespace-collapsed provider input; neither original bytes nor filename is sent to the provider.

Fixed failures: `attachment_unsupported`, `attachment_invalid`, `attachment_too_large` (422), `attachment_timeout` (408), `attachment_busy` (503), existing `thought_too_short` (422), malformed multipart/request overflow `invalid_request` (400), and existing local authorization errors (403). Errors do not echo filename, bytes or parser diagnostics. Workspace recovery lets you select another file; nothing is silently shortened. No CLI file/path option is added. Proof uses task-created files, the real loopback HTTP server/native Chrome and fake drafting: `cargo test -p syncloom-server --test attachments`. This is bounded text-file support, not completion of old PDF/image intake.

## URL sources

Use **Fetch URL only** on the same workspace composer for one source you have permission to use. This is separate from **Draft a piece** and **Suggest destinations first**: those continue treating links as plain text. Fetching calls no drafting provider and approves no source, model or account. It grants, schedules and publishes nothing.

Retrieval is disabled unless the operator sets `SYNCLOOM_SOURCE_HOSTS` to a comma-separated list of authorized exact ASCII DNS hosts and restarts the studio. Case and surrounding whitespace normalize; duplicate hosts deduplicate. Empty entries, URLs, wildcards, ports, IP literals and trailing dots refuse startup. Listing one host never permits its subdomains or redirect destinations automatically. No specific host or Internet request is authorized by this documentation.

Allowed source URLs use HTTP/HTTPS on standard ports without credentials, query or fragment. Every DNS answer must be public; mixed answers fail. Each of at most three redirects is resolved, validated and connection-pinned again; HTTPS cannot downgrade to HTTP. Environment proxies, credential/cookie reuse, retries and subresource requests are disabled. The ten-second total network budget includes DNS and every hop/body. UTF-8 HTML/plain text only, at most 262144 response bytes and 8000 extracted characters; compressed/non-UTF-8/binary/large responses fail explicitly rather than silently truncating. Authenticated retrieval and JavaScript rendering are unsupported; a public login/shell page may yield its own text, not the intended article. HTML entities decode; head, script, style, template and noscript text is excluded. This is broad text extraction, not a crawler or general readability engine.

`POST /v1/capture/url` takes exactly `url` and returns `source_revision`, `source` and `suggestions`. Source records retain the requested URL as `raw_input` and `retrieval` with `final_url`, UTC `fetched_at`, `content_sha256` of the response bytes and complete `extracted_text`. The existing capture store owns the immutable snapshot; no parallel source store or events system is introduced. Add `source_revision` with that exact extracted `text` to existing preview and confirm bodies. The preview revision binds provenance and selection. Unknown receipts, changed text and stale selections conflict. Confirm never refetches, and duplicates return the original drafts even after restart. Both the preview and saved review show provenance.

Treat remote text as untrusted data. Preview requires explicit permission/provider-transfer confirmation; only its text goes to the configured drafting provider, never system instructions or tools. This does not prove factual accuracy or prompt-injection resistance. Review the generated draft before any separate approval. Local capture/piece files hold source content; audit events and request logs never contain it or the URL.

Failures are `source_not_configured` (503: configure authorized exact hosts and restart, or paste your own text), `source_not_allowed` (422: use a permitted public text URL), `source_fetch_failed` (502: unsupported/oversized/failed source or redirect limit), and `source_timeout` (504). Fewer than eight non-space extracted characters uses existing `thought_too_short`. Browser errors retain visible Workspace recovery without echoing the submitted source.

Proof uses controlled loopback sources and a fake drafting provider through the explicit compile-time `test-source` seam. That seam maps only fixed fixture hosts after the real address-policy check; production binaries expose no runtime private-address bypass. This is not public Internet compatibility or TLS/DNS live-site proof. Test command: `cargo test -p syncloom-server --features test-source --test url_intake --test logs`. Real source fetches, accounts and publication require their own authorization.

## Capture before drafting

Use **Suggest destinations first** on the same workspace thought form when you want help choosing a format. The Draft for checkboxes apply to immediate drafting; the suggestion path asks you to select destinations on its next page. Supply only text you own, not third-party excerpts. It suggests formats and light edits from text length and the presence of links, without a model call, connection probe, URL retrieval or saved piece. Heuristic weights in the JSON response are inherited hints, not measured success probabilities.

Choose at least one suggestion, then **Preview selection**. Read the complete source and the selected destinations. This is not yet generated copy, a saved draft, or an approval. **Change destinations** preserves the source; **Start over in workspace** begins again. **Confirm and draft** sends the selected source to the existing drafting provider and creates pending-review pieces only. Review each generated piece through the ordinary review screen. Capture cannot approve, grant, schedule or publish.

`POST /v1/capture/suggest` takes exactly `text`; `/v1/capture/preview` takes `text` and `channels`; `/v1/capture/confirm` adds `expected_revision` from preview. URL and attachment preview/confirm also carry the optional acquisition `source_revision` described above. All use the existing session/Host/Origin guards. Unknown fields, duplicate/empty selections, unsupported channels and changed revisions are refused. A completed duplicate returns the same group and piece ids without calling the provider again, including after restart. An interrupted durable claim returns `revision_conflict` instead of drafting blindly; inspect Saved pieces before starting another capture. A documented provider failure leaves no pieces and releases the claim for retry. No automatic claim repair or background recovery runs.

## HTTP session handshake

The standalone CLI calls Studio directly. HTTP API clients must fetch `GET /v1/session`, read `{"token":"..."}`, and send the token once as `X-Syncloom-Token` on state-changing calls. Forms carry the same token once in their `csrf` field. The token is unpredictable, memory-only and changes with every server start; it is never a URL parameter, cookie or logged field. Do not persist it in scripts or source control.

Every route, including unknown routes and assets, checks the exact bound `127.0.0.1:<port>` Host. A supplied Origin must be the single exact `http://127.0.0.1:<port>` value. Cross-site and same-site fetch metadata are rejected even if Origin is absent; native clients may omit both. Rejections use `host_not_allowed`, `origin_not_allowed` or `session_required` before any model call or mutation. No response contains CORS headers.

All responses are no-store and nosniff, with a same-origin referrer policy (no off-origin disclosure), and have restrictive CSP. Pages cannot be framed and scripts are forbidden. Verified PDFs alone allow same-origin framing for the inline preview; off-origin framing is still forbidden. These controls defend the web boundary against cross-site requests and DNS rebinding, not malware already running on the laptop.

## Saved-piece discovery

`GET /v1/pieces` returns `{"pieces":[...],"next_after":"..."}` in ascending piece-id order, up to twenty records. Pass `next_after` as `after` for the next page; null means the end. The home screen uses this same after-only traversal, not an in-page status/channel filter. Empty stores return `{"pieces":[],"next_after":null}`. An invalid cursor returns `invalid_request`; corrupt selected records or symlinks return `internal_error` instead of silently hiding data. Temporary interrupted writes are ignored. Concurrent inserts before the cursor appear when starting a new traversal, not retroactively inside an existing page.
