Publishing to Your Own YouTube Channel from a Local Rust App: API, Quota and Verification (October 2026)

Bottom line: build the official-API path now as a hybrid of A and C. Use an External OAuth client set to “In production” but left unverified under Google’s personal-use exemption, rather than “Testing”, so refresh tokens don’t expire after 7 days. Upload resumably with privacyStatus=private, read the returned status back, then publish by publishAt or by hand. Details

1. Refresh tokens: Testing vs. Production


Confirmed (Google Identity “Using OAuth 2.0 to Access Google APIs”): “A Google Cloud Platform project with an OAuth consent screen configured for an external user type and a publishing status of ‘Testing’ is issued a refresh token expiring in 7 days, unless the only OAuth scopes requested are a subset of name, email address, and user profile.” google YouTube scopes are not in that exception, so the 7-day expiry applies.
Other expiry triggers still apply in production: 6 months unused and user revocation. There is also a cap on live refresh tokens. Google’s “Using OAuth 2.0 to Access Google APIs” page gives no number for it, saying only that a token can fail when “The user account has exceeded a maximum number of granted (live) refresh tokens,” and that per-client-user and per-user limits “are different.” Don’t re-run consent in a loop.
Production, unverified: Google’s Cloud help says unverified apps show the unverified-app screen and are “limited to 100 new users until it is verified.” google Personal-use apps with fewer than 100 users are exempt from verification. google +2 For an owner-only app this is a one-time click-through.
Testing mode details: only listed test users can authorize, the unverified screen and 100-user cap still apply, and tokens die on day 7 with invalid_grant. google +3


2. OAuth verification vs. YouTube API Services audit


Google OAuth app verification (B) is a Google Cloud process. It applies to sensitive or restricted scopes for apps that don’t meet an exemption, nylas and its purpose is to remove the unverified screen and the 100-user cap. google It does nothing for YouTube quota or the private-lock rule. For an owner-only app it is not needed.
YouTube API Services compliance audit is run by YouTube’s API team via the “Audit and Quota Extension Form”. Per the July 1, 2021 revision entry and the Quota and Compliance Audits guide, it is required to get more than default quota. googlegoogle Per the July 28, 2020 entry it is the documented way to lift the private lock. Under the June 1, 2026 granular-quota change, increases are requested per method through the same form. googlegoogle You may be asked for test accounts and a review of your client against the Terms, Developer Policies and Required Minimum Functionality (for example, the user must be able to set a title). googlebitbucket
Timeline: Google gives no SLA. Its “Quota and Compliance Audits” guide says only “A member of YouTube’s API Services team will contact you as soon as possible.” First-hand reports from personal-use developers in the porjo/youtubeuploader issue #86 thread range from about 3 months to 6 months. At the fast end, the author of the jenslys/autovod README on GitHub, who applied for two projects, writes: “It took around 20 days from submission to them accepting the audit.” Can a one-person app pass? Yes: at least two personal-use developers in the issue #86 thread report approval. No 2026-dated first-hand solo approval was found. Commenters note the form is written for public apps (users, retention, UI), so describe the app plainly: one channel, owner only, every upload approved by a human, no third-party data.
Inactivity: the same thread reports that projects can lose access after 90 days unused, and one approved developer does periodic private dummy uploads to keep it alive. githubgoogle


3. The forced-private rule: what is actually true in October 2026


For the lock: the July 28, 2020 revision entry says uploads from “unverified API projects created after 28 July 2020 will be restricted to private viewing mode” until audit. YouTube Help “Videos locked as private” (answer 7300965) says such videos “will not be able to appeal. You’ll need to re-upload the video via a verified API service or via the YouTube app/site.” googlegoogle
Against the lock: the current videos.insert and Videos resource pages (last updated 2026-10-15) state “Videos uploaded from unverified API projects are not restricted to private viewing mode.” No revision-history entry announces this reversal, and some localized or cached copies of the same page still carry the old banner. googlegoogle
Field evidence: every first-hand report found shows locking. In porjo/youtubeuploader issue #86 (opened Aug 24, 2020), users quote YouTube’s notice that “the video was uploaded using a third party tool that failed our verification.” The 2026 PyPI package youtube-cli-uploader still warns that “API projects that have not completed YouTube’s compliance audit may be restricted to private uploads.” The only 2026 claim that the lock is gone is a GitHub comment that reasons from the new doc wording without a test upload.
Workaround “change privacy later in Studio”: if a video is locked, Studio does not let you change it (Help page above; users in issue #86 report “can’t be changed to public”). googlegithub Uploading as private and publishing later works only if the project is not locked. That is exactly why the first upload should be a throwaway private test, checking both the API response and Studio.
Interpretation: the safest reading is that the doc sentence may reflect a real policy relaxation that hasn’t been announced, or it may be an error. Design so either outcome is fine: upload private, verify, and fall back to C until the audit clears.

5. Terms on automation, AI and data retention


Developer Policies III.E.4: Authorized Data other than statistics may be stored for no more than 30 days, then refreshed or deleted. Statistics may be kept longer, but you must re-verify authorization every 30 days. fandomgithub On revocation through your app, revoke the token and delete Authorized Data. The compliance guide gives 7 days for in-app deletion requests and 30 days when authorization can’t be verified. githubgoogle Since May 4 / June 1, 2026, the new “Additional policies on derived metrics and data storage” allow storing statistics beyond 30 days only for audited projects that apply for it. google For a local app, keep a 30-day refresh job and a “disconnect” button that revokes and purges.
No sharding: don’t create multiple Cloud projects to multiply quota (Complying with Developer Policies guide). google
Automation: no clause found that bans human-approved, API-based uploads to your own channel; the human-approval step is a strong compliance signal. notifySubscribers=false exists for bulk uploaders. google
AI content: disclose realistic altered or synthetic content via status.containsSyntheticMedia. google YPP’s “repetitious content” policy was renamed “inauthentic content” on July 15, 2025, targeting mass-produced, templated videos. A YouTube statement carried by Social Media Today and Yahoo Finance in July 2025 said “channels that use AI in their content remain eligible for monetization… creators are required to disclose when their realistic content is altered or synthetic.” YouTube Creator Liaison Rene Ritchie called the change “a minor update to YouTube’s long-standing YPP policies.”

7. Rust stack


google-youtube3 (Byron/google-apis-rs): latest is 7.0.0+20251222, generated from the Dec 22, 2025 discovery revision. The matching google-youtube3-cli 7.0.0+20251222 was published 2026-01-01; the library’s exact publish date was not confirmed, and is presumably the same release. docsgithub It depends on google-apis-common ^8 and optional yup-oauth2 ^12, and offers resumable upload (upload_resumable) plus simple and multipart upload through google-apis-common. docslib Maintenance: generated and periodically republished. The schema predates brandPartner (Jul 2026) and comments.imageUrl (Sep 2026), so recent fields may need raw JSON. containsSyntheticMedia (2024) is included.
yup-oauth2: latest 12.1.2 (2026-01-07); previously 12.1.1 (2025-11-29). About 1.6M downloads/month. docslib InstalledFlowAuthenticator with InstalledFlowReturnMethod::HTTPRedirect gives you the loopback desktop flow, and persist_tokens_to_disk handles token storage. docs Actively maintained.
Alternative: reqwest plus the resumable protocol directly. POST uploadType=resumable with the JSON metadata, receive a session URI, PUT chunks in multiples of 256 KiB with Content-Range, and on interruption query bytes */total and resume. This is about 200 lines of code, gives full control over current fields, and avoids generated-code churn. Pair it with yup-oauth2 or the oauth2 crate. Recommendation: use yup-oauth2 for auth and either crate for upload. Hand-rolled reqwest is preferable if you want the newest fields and simple dependencies.

Recommendations


Day 0: Create a Cloud project. Enable the Data API v3 and Analytics API. Set up an External consent screen and a Desktop OAuth client. Set publishing status to In production and do not submit for verification. Authorize once via the loopback flow and persist the token.
Day 0: Submit the YouTube API Services Audit and Quota Extension Form describing an owner-only, human-approved publisher. Expect weeks to months.
Day 1: Make a throwaway resumable upload with privacyStatus=private, then try flipping it to public in Studio. If it is not locked, proceed with A-in-production: upload private, set publishAt, add thumbnail, captions and playlist via API. If it is locked, use C for publishing (Studio upload with app-prepared title, description, tags, thumbnail and captions files) and keep the API for reads, comments and metadata on Studio-uploaded videos until the audit passes.
Phone-verify the channel before relying on thumbnails.set.
Set containsSyntheticMedia honestly per upload, implement the 30-day refresh/purge, and make a low-cost API call at least monthly so the project doesn’t go 90 days idle. google
Skip B unless you ever add other users.
