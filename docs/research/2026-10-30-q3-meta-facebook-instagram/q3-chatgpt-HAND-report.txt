Instagram vs Facebook APIs

Use the Instagram Graph API for Instagram content and the Facebook (Page) Graph API for Facebook Page posts. Meta offers two login flows for Instagram business accounts: Instagram Login (standalone IG login) or Facebook Login (via a linked Facebook Page). Both call the same Instagram Graph API, but the IG login path does not require a connected Facebook Page. In practice, either path works; many SDKs/examples use Facebook Login for business accounts that already have a Page. Content support is roughly:

Facebook Page API: you can post text, links, photos (POST /{page-id}/feed or /photos), videos (/videos), and Reels (via POST /{page-id}/video_reels in recent API versions) to your Page. Multi-photo posts (carousels) aren’t a single endpoint but can be done by uploading photos as unpublished and then attaching them in a /feed post. You can also tag location and add alt-text (the Graph API accessibility_caption field) on photo uploads. You can moderate comments and read Page and post insights with permissions like pages_read_engagement and pages_manage_posts. Page tokens (obtained from a user token via /me/accounts) are used to authenticate Page calls and typically do not expire as long as the user token is refreshed periodically.
Instagram API: for a Professional (Business/Creator) account, the Content Publishing API lets you publish to Feed and Reels. Supported media types include single-image posts and videos, Reels, Stories and (recently) carousels. You publish by creating a “media container” (POST /{ig-user-id}/media with media_type = IMAGE, VIDEO, CAROUSEL_ALBUM, or STORY), then POST /{ig-user-id}/media_publish. (Carousels up to 10 items are supported by using media_type=CAROUSEL_ALBUM and specifying child media IDs.) You can include alt-text (caption field for images, or separate accessibility field for videos) and location tags on Instagram posts. After publishing you can add a “first comment” by calling the /comments edge on the new media object (the API allows posting comments programmatically). You can read your own posts, comments, and insights via the Instagram Graph API, but you cannot scrape public Instagram posts except via limited “Hashtag Search” or “Business Discovery” endpoints (which only work on public business/creator accounts).
Authentication & Tokens

All Graph API calls use an access token. The usual flow is: log in via Facebook or Instagram Login to get a short-lived user token, exchange it for a long-lived (60-day) user token, then retrieve a Page access token (for Facebook Pages) or use that to access connected Instagram Business accounts. Long-lived tokens must be refreshed roughly every 60 days (by calling the refresh endpoint before they expire) to avoid downtime. Page tokens derived from long-lived user tokens are effectively long-lived themselves (they auto-refresh when the user token is refreshed). Instagram tokens behave similarly once you have an IG Business account linked to a Page. (If your app is for a single founder and only your own accounts, you’ll manage these tokens manually and rebuild them with each login.)

App Mode and Access Levels

By default a Meta app starts in Development mode with Standard Access. In this mode, the app can call all relevant APIs on behalf of its own admin/developer/tester accounts without review. In practical terms, this means you can fully develop and test posting to your own Pages and IG account with no App Review or business verification: Standard Access allows any user who has a role on the app (you, as admin) to authorize and use the app.

If you later need to serve other businesses or clients, you must go through App Review to get Advanced Access for permissions like pages_read_engagement, pages_manage_posts, or instagram_content_publish. The review process typically takes several weeks (common estimates are 2–8 weeks) and requires a detailed screencast, privacy policy, terms of service, and (for advanced access) business verification (proof of legal entity). But for a single-user tool posting only to your owned accounts, no review or verification is needed – Standard Access covers it.

Scheduling Posts

The Graph API supports scheduling posts natively. For Facebook Pages, the /feed endpoint accepts a scheduled_publish_time parameter (with published=false) to queue posts. For Instagram, the Content Publishing API also supports scheduling. Meta explicitly lets developers schedule posts (only single-image/video, not carousels) to business accounts. In fact, Instagram Business accounts are limited to 25 API-published posts per 24-hour period. To schedule, you set the future publish time when creating the media container or publishing it. Alternatively, you can do scheduling in your own app (“local scheduling”) by holding posts and calling the API at the chosen time – either way ultimately uses the Graph API publish endpoints. Note: Meta’s own tools (Creator Studio/Business Suite) also allow scheduling Page posts, but Instagram scheduling is only via the API.

Key Limits and Policies
Rate Limits: Instagram’s API uses a business-use-case (BUC) limit: 4800 × (rolling 24h impressions of the IG account) calls per day. In practice this means accounts with few followers or impressions hit the cap quickly. (Facebook Page rate limits are generally high/not publicly documented for normal usage, but heavy use could also be throttled.) Additionally, Instagram limits API scheduling to 25 posts/day as noted.
Content Policies: You must follow Meta’s Platform Policies. This means no unauthorized automation or data scraping, no spamming or repetitive content, and compliance with any AI content rules. (For example, as of 2023–26 Meta requires labeling certain AI-generated ads or content. All user data must be handled per Meta’s data use policy.) Your app will also inherit Facebook’s Community Standards for content posted. In short: treat the API posts as if you were using the normal apps, and don’t break any of Meta’s terms. (For specifics, see the Facebook Platform Terms and Instagram API policy.)
2025–2026 Changes to Watch For

Meta has been simplifying its APIs. Notably:

Graph API Versions: Graph API v20.0 and older are being retired. In fact, v20.0 was removed on Sept 24, 2026 (you must be on v21.0 or newer). Plan to use the latest Graph API (v25+ as of early 2026).
Instagram API Changes: In Jan 2025 Meta replaced legacy Instagram objects with new IG-prefixed ones. Starting in API v22+, the main “reach/impressions” metric is replaced by a “views” metric, and older metrics like plays, impressions, and clips_replays_count are deprecated. For example, IG media insights now report views for Feed, Story, and Reels, and may no longer return impressions for new media. Always check the latest Graph API changelog for removed fields before relying on them.
Instagram Basic Display API: This older, simpler IG API was shut down on Dec 4, 2024. All login/data access now requires an Instagram Business/Creator account and using the Instagram Graph API (via IG or FB login).
Development & Testing

In Development mode your app can only access accounts you’ve explicitly added as Admin/Developer/Tester. This is enough for a solo founder. You should add yourself as an app user and then use the Graph API Explorer or your code to fetch a user token, extend it, and test all endpoints against your own Page and IG account. No special “sandbox” is needed beyond this. When you’re ready to go live for just your use, you can simply switch the app out of dev mode or keep it in dev mode (since you are the only user) – either way your admin role allows full use.

Rust Clients and Tools

Meta does not provide an official Rust SDK. You can use any HTTP/JSON client (e.g. reqwest or hyper) to call the Graph API endpoints, or look at community libraries. There is at least one unofficial crate (e.g. facebook-rs) but it appears out-of-date. In practice you’ll write your own Graph API calls in Rust. (For handling OAuth, you can hit the Facebook OAuth endpoints directly or use an OAuth client library.) Testing can be done with simple tools (Postman) before coding.
