DECISION: How a single-operator, local-first Rust application renders 1080x1350 PNG images and multi-page PDF carousels from designer templates.
OPTIONS: (R1) drive headless Chromium from Rust over the DevTools protocol (chromiumoxide, headless_chrome, or a thin CDP client) with HTML/CSS templates; (R2) Typst documents compiled to PDF and PNG; (R3) SVG templates rasterized with resvg/tiny-skia, PDF from a Rust PDF library (printpdf, pdf-writer, svg2pdf); (R4) a desktop webview's own PDF/PNG output.
CONSTRAINTS: Rust for first-party code; macOS host, output also viewed on a phone; deterministic output for snapshot tests; web-font and gradient fidelity; multi-page PDF merged into one file of small size with selectable text; no paid service. As of October 2026.
EVIDENCE: Today's pipeline is Python plus headless Chromium turning HTML/CSS templates (gradients, web fonts, inline SVG charts) into PNGs and per-slide PDFs merged into one document, with 49 rendering tests. There is no Rust rendering evidence yet.
QUESTION: For producing these assets, compare R1-R4 on visual fidelity (fonts and ligatures, gradients, SVG filters, blend modes, emoji), byte-stable or pixel-stable output across runs and machines, packaging and binary size on macOS (including how a Chromium binary is found or shipped and its licence), cold-start and per-page latency, PDF size and text accessibility, crate maintenance (last release, open issues), and published examples or benchmarks. Name any PDF/X or LinkedIn document-upload gotchas (fonts embedded, page size, file size limit).
WOULD CHANGE THE ANSWER: if Typst or resvg reaches pixel-stable output with acceptable typography on the existing gradient and font design, drop the Chromium dependency; if neither does, keep R1 and treat Chromium packaging as a task.
PUBLIC CONTEXT: A pre-launch single-user content studio; the founder reviews every asset before an explicit publish.
